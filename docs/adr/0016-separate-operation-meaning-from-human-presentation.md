# Separate operation meaning from human presentation

Status: Accepted

MCV separates operation meaning from Human Presentation. Operation-specific renderers classify already-known facts into a small closed set of Presentation Roles; the Presentation module maps those Roles to shared symbols and destination-specific styling but never infers business meaning from text, counts, or field names. Attention and Danger are therefore visual groupings, not new domain states: wording continues to distinguish Drift, pending work, dirty state, destructive actions, blocked operations, and errors. Human wording and layout may change during the one-time migration, while operation meaning, exit codes, Plan/Apply safety, JSON, and MCP remain compatible.

Output capabilities are resolved only after the destination is known. Review Artifacts, JSON, and MCP never contain ANSI; `NO_COLOR`, `FORCE_COLOR=0`, and `TERM=dumb` disable color in that order, while a nonzero `FORCE_COLOR` may enable color for other human terminal output even without a TTY. Human Plan and Result documents stay coherent on stdout even when they contain Danger roles or exit nonzero; invocation errors, failures that prevent an Operation Report, and Artifact fallback diagnostics use stderr. The symbols `✓`, `!`, `?`, `×`, `•`, and `·` remain stable across color modes, with complete wording as the authoritative accessible signal rather than an ASCII parallel presentation.

Commander continues to own help, version, usage layout, and errors raised before an MCV command handler runs; the Presentation boundary begins inside MCV's handlers. Human documents expose structured blocks for titles, fields, statuses, lists, Issues, paths, commands, literal content, Diffs, Review references, and next actions, without a raw-line or pre-rendered ANSI escape hatch. Literal and Diff content remains faithful while adapters own its framing and terminal-safe rendering. Selection, enabled state, ownership, and focus stay orthogonal to Presentation Role: selecting a destructive item never turns Danger into Success, and focus emphasis never changes its operation meaning.

Review Artifacts are rendered through the plain adapter and checked again for forbidden terminal controls immediately before writing. A failed check prevents Artifact creation and uses the existing inline fallback; it never silently strips or rewrites reviewed content. `--verbose` continues to print complete details without suppressing an otherwise-required Artifact, because terminal detail level and the private short-lived review file are separate concerns.

A human document retains explicit Summary, optional Overflow Summary, Details, Next Actions, and Detail Policy regions, but each region contains structured blocks rather than rendered lines. Presentation Roles apply to fact blocks, not arbitrary character ranges; adapters limit styling to symbols, labels, and short status phrases, while prose, long values, Literal content, and Diff content remain neutral. Paths, commands, IDs, and similar values are represented by content kind rather than renderer-selected colors.

The shared Issue block maps `error`, `decisionRequired`, `warning`, and `notice` to Danger, Decision, Attention, and Information, respectively, and orders them in that sequence while preserving source order within each severity. Destructive changes remain change facts rather than Issues. Presentation also renders the semantic question for interactive prompts, including the operation, selected count, target, Decision marker, and unchanged default choice; the input mechanism remains outside Presentation, and prompts never enter Review Artifacts.

Artifact validation permits ordinary Unicode, line feed, and tab. It rejects escape, every other C0 control, delete, and the C1 control range; platform newline encoding belongs to the adapter, and reviewed content cannot introduce a standalone carriage return. This validation applies only to Human Presentation and does not inspect or change Repository, JSON, or MCP data.

The Terminal adapter uses visible-width-aware hanging indentation when a TTY width is available, avoids layouts that require horizontal tables, and falls back to a stable single column when width is unknown. Non-TTY and Artifact output do not hard-wrap logical fields, and Literal, command, and Diff content is never reflowed. Review references use one platform-native absolute path, without a duplicate file URL or terminal hyperlink.

Ink consumes the shared Roles, symbols, visual tokens, Issue mapping, and status-classification helpers, but not the line-oriented document renderer; Capture and Profile retain independent interactive layouts and state. Diff blocks carry explicitly classified metadata, context, add, and remove lines so the Terminal adapter never guesses semantics from arbitrary content, while the Plain adapter preserves standard unified Diff text.

Human output may be emitted only by the Presentation gateway, Commander, or the Ink runtime; JSON uses a separate structured-output gateway, and command handlers do not print human prose directly. A static architecture test protects that boundary and prevents ANSI literals in command and renderer code, while terminal-control output remains confined to the Ink runtime. The migration removes the old coloring helpers and string-array document model without compatibility wrappers.

For color capability, an absent `FORCE_COLOR` uses normal TTY detection, `0` disables color, and any other present value — including an empty or unrecognized value — enables the same basic ANSI palette; values `1`, `2`, and `3` do not create color-depth variants. `NO_COLOR` and `TERM=dumb` retain higher precedence and disable styling.

Role assignment remains fact-specific rather than coloring a whole report by its highest severity. No change, already satisfied, in sync, and Git clean are quiet Success facts; a non-Git Repository, a disabled IDE, and absent optional Surfaces are Muted; an enabled but undetected IDE is Attention; missing required Repository, target, variable, managed content, or topology is Danger. Pending add or modify, Drift, and dirty state are Attention, while every delete, topology replacement, and Advanced Cleanup candidate is Danger regardless of selection. Overview itself stays informational and presents these facts independently.

A Plan's lead Role describes execution readiness rather than the most severe item it contains: an error or block is Danger, an unresolved choice or required authorization is Decision, satisfied Apply preconditions are Success, and no selected change is a quiet Success. A safely unselected destructive candidate remains a Danger fact without making the Plan falsely appear failed. Presentation never invents claims about write safety: cancelled or interrupted output says that nothing changed only when the Result proves no durable write or verified rollback; unknown or failed rollback is Danger with an inspection action. Operation contracts, not Roles, determine exit codes.

Human documents render non-empty regions in this order: outcome, scope and identity context, primary counts and statuses, errors and decisions before warnings, selected and destructive changes, notices and quiet metadata, Review reference, Next Actions, then an interactive prompt when required. Next Actions distinguish prose instructions from directly copyable commands; renderers choose their content and order, while Presentation supplies the shared label and styling.

In line-oriented, non-TTY, and Artifact output, `NO_COLOR` means no ANSI at all. In an Ink TUI it disables SGR color and text styling while allowing the cursor, alternate-screen, and other control sequences required for interaction; visible markers and wording preserve every state. Focus uses a stable `›` marker with optional Information emphasis, selection uses an explicit checked or unchecked marker rather than Success, a selected destructive fact remains Danger, and a confirmed warning retains its Attention fact alongside a separate confirmation marker.

Dedicated TUIs may show an immediate Result frame, but after exit they return typed outcome facts rather than pre-rendered summary strings. Once the alternate screen and input mode are restored, Presentation emits a concise line-oriented Result or diagnostic for terminal scrollback; Capture and Profile use the same boundary, and any Review path truncated inside a TUI is printed in full afterward. Output capability is computed per destination stream — stdout, stderr, or forced-plain Artifact — and documents never read global process state.

On every TUI exit or failure, Ink rendering stops and the runtime restores raw mode, console mode, cursor, and alternate screen before Presentation renders the typed outcome or diagnostic and the command sets its existing exit code. Presentation adapters never take ownership of terminal restoration.

The one-time migration covers bare Overview and Status, Discover, Init, Repository inspection, Bind, Unbind, Migrate, Capture, Deploy, Restore, every line-oriented Profile command, both dedicated TUIs, handler-owned errors and prompts, cancellation and interruption, no-change and post-TUI outcomes, Review Artifacts, and fallback diagnostics. Commander-owned parsing output, JSON, MCP, and Ink's necessary terminal controls remain outside the boundary. Presentation is an internal deep module rather than an exported npm API; the packaged CLI remains its only public contract.

Acceptance avoids a full command-by-state-by-platform Cartesian product. Every human command receives at least one packaged scenario, while the packaged suite collectively covers every important outcome and output destination; focused module tests exhaust blocks, Roles, capability precedence, and control validation; architecture tests prove the legacy paths are gone; macOS PTY and real Windows ConPTY cover interaction and restoration. Small fixed adapter fixtures may assert exact output, but packaged tests assert stable block order, complete key wording, symbols, Role-specific ANSI, forbidden-control absence, exit codes, and filesystem safety without snapshotting dynamic full Plans, Diffs, paths, UUIDs, or entire TUI histories.

A release requires type checking, the full test suite, a clean production build, packaged CLI and PTY or ConPTY execution after that build, packaged help, representative human output, package dry-run inspection, a check that rebuilding leaves tracked `dist/` unchanged, and a clean diff check. Windows CI must exercise native Review paths and control-free Artifacts, Unicode symbols, basic ANSI and `NO_COLOR`, both dedicated TUIs, and original console-mode restoration after normal exit, cancellation, interruption, and render failure; macOS or mocked coverage cannot substitute for it.

Review overflow keeps the existing 40-line and 8-KiB thresholds and measures the unwrapped Plain rendering of Details, independent of ANSI and terminal width, so destination capabilities never change the Artifact decision. Details is a complete standalone review view rather than an incremental tail of Summary; an Artifact contains its fixed privacy and non-authorization header followed by Details, while Summary, Review reference, prompt, and terminal-only Next Actions stay outside. `--verbose` renders that same complete Details view.

If forbidden content controls prevent Artifact creation, the Artifact remains unwritten and the Terminal fallback presents those controls as explicit reversible `\u{...}` notation with a stderr diagnostic; Repository, Operation Report, JSON, and MCP data remains untouched. Optional Artifact failure does not change the Operation Result. Failure of the primary human renderer is a command failure that reports the already-known operation status and identifies presentation as the failed stage, without claiming that an earlier Apply was rolled back or rewriting its Report.

Plain output is an ANSI-free human representation, not a machine-stable record format. Its meaning remains deliberate, but field positions and byte-for-byte wording are not compatibility contracts; automation uses JSON or MCP. This distinction does not weaken the packaged CLI as the public acceptance seam for Human Presentation.
