# MCV

A personal AI IDE configuration collection, management, and cross-device deployment tool. MCV captures a developer's AI productivity data into a user-owned Repository and deploys it to any new device.

## Language

**Canonical（通用主权层）**:
Configuration content that is semantically shared across multiple AI IDEs — rules, Skills, MCP definitions, workflows. The defining criterion is cross-IDE reusability, not cross-device portability (all three layers are cross-device portable).
_Avoid_: "universal config", "shared config"

**Native（IDE 原生个性层）**:
Configuration that only has meaning within a single specific IDE, stored in its original format. Native config is still cross-device portable via the repository.
_Avoid_: "IDE-specific", "per-IDE"

**Local/Runtime（本机运行状态层）**:
Device-bound data that an Adapter does not declare as transferable configuration — caches, logs, session state, device identifiers. Secret-like content is not automatically Local: a plaintext key inside supported configuration remains configuration data.
_Avoid_: "temporary", "transient"

**Repository（数据仓库）**:
A user-owned local directory that serves as the single long-term source of truth for all confirmed AI IDE configuration. Git is one recommended but optional way to version, back up, and transfer this directory; a non-Git directory is an equally valid Repository and is not a warning state. "Source of truth" means the authoritative human-confirmed version, not the real-time latest state — between captures, the device may hold newer unconfirmed changes, and that is by design.
_Avoid_: "sync target", "backup"

**Adapter（适配器）**:
The single per-IDE interface (`IdeAdapter`) that MCV's core uses to detect, capture, and deploy configuration for a specific IDE. Each Adapter internally composes a CanonicalTransformer and a NativeFileHandler.
_Avoid_: "plugin", "driver", "connector"

**CanonicalTransformer**:
The internal component of an Adapter responsible for semantic conversion between MCV's unified Canonical format and a specific IDE's format (e.g. unified rules → `CLAUDE.md`).
_Avoid_: "converter", "mapper"

**NativeFileHandler**:
The internal component of an Adapter responsible for path discovery, file read/write, and path parameterization — without understanding the semantic meaning of configuration fields.
_Avoid_: "file copier", "sync engine"

**Overlay（字段级合并）**:
The mechanism for handling config files that contain both MCV-managed and IDE-native fields. Uses a managed-whitelist strategy: only `managedPaths` are explicitly declared; every undeclared field defaults to Native ownership and is preserved untouched. A small `localPaths` list excludes known device-bound fields.
_Avoid_: "merge strategy", "field mapping"

**Drift（漂移）**:
A local modification to a unit that MCV considers managed — a field in `managedPaths`, or a Managed Block in a project-level rules file. Capture reports drift separately from normal native changes, because drifted fields were generated by MCV and should not be silently absorbed back as native config.
_Avoid_: "conflict", "divergence"

**Pending Deployment Change（待部署变化）**:
A difference between the current Repository's desired managed state and the current device that would produce an add, modify, or delete candidate in a Deploy Plan. It is distinct from Drift, which is a local managed-field change measured against the Baseline Snapshot.
Status summarizes a multi-file Skill projection as one package action per Surface and excludes unselected Advanced Cleanup candidates; the Deploy Plan retains file-level changes for review, preconditions, and Apply.
_Avoid_: "sync status", "unsynced"

**Restore Conflict（恢复冲突）**:
A local content or topology change made after the latest deployment that would be overwritten by Restore — including file edits, replaced directories, retargeted or removed managed-link projections, and other node-type changes. A Restore Conflict blocks restoration in the current beta and is distinct from Drift, which describes managed-field changes relative to a Baseline Snapshot.
_Avoid_: "restore drift", "extra confirmation"

**Capture（收集）**:
The reverse operation that collects supported device-side configuration changes back into the Repository. Configuration values are preserved faithfully; only known absolute paths are parameterized for portability. The user confirms the exact form that will be written, including any plaintext keys.
_Avoid_: "sync back", "import"

**Canonical Rules（通用规则）**:
A single Markdown file (`common/AGENTS.md`) containing the user's cross-IDE development rules. Named `AGENTS.md` to match mainstream AI IDE convention. The CanonicalTransformer renames/places it per IDE target (e.g. `CLAUDE.md` for Claude Code). Multi-file rule sets are deferred to future versions.
_Avoid_: "rule templates", "rule library"

**MCP Registry（MCP 注册表）**:
A Canonical YAML file (`common/mcp.yaml`) that stores the core definitions of MCP servers (name, command, args, env variable references). Surface-specific overrides (e.g. timeout, disabled, headers, or alternate launch commands) live in `ide/<ide-or-surface>/mcp-overrides.yaml` and are merged on top during deploy. Override priority: Surface-level > Canonical base.
_Avoid_: "MCP config", "server list"

**Skill**:
A reusable instruction package stored as a directory containing a `SKILL.md` file (with YAML frontmatter) and optional subdirectories (`scripts/`, `examples/`, `resources/`, `references/`). Skills live in `common/skills/` as Canonical content. On device, one physical package may be projected to several IDE Skill Surfaces through managed directory links; those projection links are device topology, not part of the portable Canonical package. Symbolic links inside a portable Skill package are unsafe content and are rejected during Capture. Global-scope deployment is a directory copy or managed-link projection to each IDE's global skills path; project-scope deployment is always a self-contained directory copy into the target project, never a link back to the Repository or HOME — no content transformation needed. IDEs that don't support Skills are skipped with a notice.
_Avoid_: "recipe", "template", "rule pack"

**Asset**:
The smallest deployable unit a Profile can reference precisely — one Canonical rules file (`rule:canonical`), one Skill package (`skill:<name>`), one MCP server definition (`mcp:<name>`), or one Adapter-declared Native config unit (`native:<target>/<file-id>`). An Asset is a stable logical identity over the existing Repository file structure, not a new physical storage format; Surface overrides and platform overrides travel with their base Asset rather than becoming Assets of their own.
_Avoid_: "component", "package", "module"

**Asset Catalog**:
The complete inventory of a Repository's Assets, deterministically regenerated from Repository content on every read — never a user-maintained index file. Catalog metadata such as display name, description, activation, and supported scopes/targets is derived from file formats and Adapter declarations, not inferred classification.
_Avoid_: "asset registry", "assets.yaml", "asset database"

**Profile**:
A named, unordered set of Asset IDs plus a short human- and agent-facing description, stored in the Repository's root `profiles.yaml`. A Profile only selects *which* assets; it carries no target platform, project, device, or install state, and supports no tags, inheritance, composition declarations, or per-asset parameter overrides. Profile IDs are immutable; display names change via `title`.
_Avoid_: "preset", "bundle", "template", "config group"

**global Profile（内置 global Profile）**:
The built-in Profile that always exists and cannot be deleted, created at migration with all then-existing Assets so that legacy deploy-everything-globally behavior is preserved. It otherwise shares the exact same data structure, editing, and deployment flow as ordinary Profiles — including being deployable to a project. Do not confuse it with the global Deploy Scope: in `mcv deploy global` the word names this Profile; in `mcv deploy dev --global` it names the scope.
_Avoid_: "default profile", "system profile"

**Unassigned**:
The dynamic set of Assets referenced by no Profile — Asset Catalog minus all Profile-referenced Assets — computed on read, never stored. Newly captured Assets land in Unassigned by default, and Unassigned Assets are never deployed, because Deploy selects assets only through Profiles.
_Avoid_: "inbox", "uncategorized", "orphans"

**Deploy Scope（部署范围）**:
Where a Deploy writes: `project` — an explicit target directory, by default exactly the current working directory — or `global` — the device's per-IDE user-level locations. Scope only drives path resolution and safety boundaries; it never changes Profile content, and any Profile may use either scope. Project is the default scope; `--target` and `--global` are mutually exclusive.
_Avoid_: "install target", "mode", "environment"

**Managed Block（受管理块）**:
A delimited region (`<!-- mcv:begin ... -->` / `<!-- mcv:end ... -->`) inside a project-level rules file whose content MCV owns and updates, while everything outside the block remains untouched user content. A locally modified block is Drift and is never silently overwritten; pruning removes only unmodified MCV blocks, never surrounding file content.
_Avoid_: "managed section", "marker region"

**Revision（Catalog / Profiles）**:
Content hashes — of the sorted Asset Catalog and of the normalized `profiles.yaml` — that act as optimistic-concurrency tokens for every Profile write and as Plan preconditions for Deploy. A writer must present the expected Revisions; a mismatch fails the operation rather than overwriting newer state.
_Avoid_: "lock", "version"

**Baseline Snapshot（基线快照）**:
A record of file hashes written to local device state after `init` or `deploy`, marking "these files are in sync with the repository at this moment." `mcv init` records a baseline at the end (a virtual deploy — no files are written, but hashes are captured). This gives subsequent `capture` runs a reference point to detect changes.
_Avoid_: "deploy record", "sync state"

**Managed Receipt（项目托管回执）**:
A minimal record stored inside a project that received a project-scope Deploy (`<target>/.mcv/managed.json`), listing which project files MCV created, their Asset IDs, and content hashes. It grants MCV cleanup ownership for safe update and prune without any cross-device project registry — MCV keeps no project list, names, or absolute paths, and the Receipt stays valid wherever the project directory moves. Deleting it only forfeits cleanup ownership and returns MCV to conservative mode. Distinct from the Baseline Snapshot, which is device-side state marking sync with the Repository for Capture drift detection.
_Avoid_: "project binding", "project registry", "install manifest"

**mcv.yaml（仓库清单）**:
The single root-level file that identifies a directory as an MCV Repository and holds all repository-level configuration: identity (`repositoryId`, `schemaVersion`, `initializedAt`), target IDE declarations, variable definitions, and capture/deploy settings. Schema v3 has no content-security policy field; schema v4 moves Profile data out of the manifest into a separate root `profiles.yaml`, leaving the manifest to identity and runtime configuration only.
_Avoid_: "config file", "settings file"

**Configuration Data Neutrality（配置数据中立）**:
MCV does not recognize, replace, exclude, mask, or block plaintext keys in supported configuration. Users may choose plaintext or `${env:*}` references. Repository files, Review Artifacts, backups, `--verbose` terminal output, and JSON can therefore contain plaintext keys; access control, encryption, transport, and disclosure risk belong to the user. Default human output may keep only a decision summary in terminal history while preserving complete details in a private short-lived Review Artifact. This does not widen discovery beyond Adapter/Skill-declared content.
_Avoid_: "secret scanner", "credential vault", "safe Repository"

**Review Artifact（审阅文件）**:
A private short-lived Local/Runtime text file containing complete human-readable review details that would otherwise flood terminal history. It is presentation data, not a persisted Plan, operation log, backup, or Apply authorization. JSON and MCP never create one; `--verbose` prints the same complete details inline without suppressing the Artifact. Artifact creation must not mutate the Repository, target, Managed Receipt, Baseline Snapshot, or device operation state.
_Avoid_: "saved plan", "audit log", "replay file"

## Example dialogue

> **Developer:** Status reports Drift in an MCV-managed field. Can Capture silently treat it as Native configuration?
>
> **Domain expert:** No. Drift is reviewed as a managed change relative to the Baseline Snapshot before it can enter the Repository.
>
> **Developer:** The Repository changed after that deployment. Is that also Drift?
>
> **Domain expert:** No. A difference from the Repository's current desired state is a Pending Deployment Change; Drift describes what changed locally after the baseline.
>
> **Developer:** Restore reports a Restore Conflict for the same path. Is that just another Drift warning?
>
> **Domain expert:** No. It means Restore would overwrite a change made after the latest deployment, so the current beta blocks the restoration until the user preserves or resolves that change.
>
> **Developer:** `mcv deploy global` writes to the device-global IDE locations, right?
>
> **Domain expert:** No — it deploys the built-in global Profile to the current project, the default Deploy Scope. Writing to device-global locations is the `--global` scope, which any Profile can use.
>
> **Developer:** The Managed Receipt records which project files MCV owns. Isn't that a Project Binding?
>
> **Domain expert:** No. The Receipt lives inside the project and records only file ownership and hashes; MCV keeps no project list, path table, or cross-device identity, and deleting the Receipt just returns cleanup to conservative mode.
